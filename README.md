# نظام إدارة المقهى — تطبيق سطح مكتب (Electron)

## المتطلبات
- تثبيت [Node.js](https://nodejs.org) (النسخة LTS) على جهازك — يتضمن `npm`.

## خطوات التشغيل والبناء

1. فك ضغط المجلد، وافتح موجه الأوامر (Terminal / CMD) داخله.
2. ثبّت الحزم مرة واحدة فقط:
   ```
   npm install
   ```
3. للتجربة السريعة (يبني الحزمة تلقائيًا ثم يفتح التطبيق كنافذة مباشرة):
   ```
   npm start
   ```
4. لبناء ملف `exe` قابل للتثبيت على ويندوز:
   ```
   npm run dist
   ```
   بعد انتهاء الأمر، ستجد ملف التثبيت داخل مجلد `release` باسم شبيه بـ:
   `نظام إدارة المقهى Setup 1.0.0.exe`

   شغّله مرتين (double-click) وسيثبّت التطبيق بأيقونة على سطح المكتب وقائمة ابدأ.

> ملاحظة: إذا كنت تبني على ماك أو لينكس وتريد exe لويندوز، الأمر أعلاه يعمل غالبًا مباشرة بفضل `electron-builder`، لكن الأضمن هو البناء من جهاز ويندوز نفسه.

## هيكل المشروع
```
main.js           نافذة التطبيق + التحديثات التلقائية + حفظ نسخة محلية من البيانات + الطباعة
preload.js        يعرض واجهة آمنة (electronAPI) للتواصل بين الشاشة والنظام
index.html        هيكل الصفحة (يحمّل dist/bundle.js وليس app.js مباشرة)
styles.css        كل التنسيقات والهوية البصرية
app.js            كامل منطق الواجهة (الشاشات، الصلاحيات، السلة...) — يُجمّع تلقائيًا
cloud.js / auth.js / firebase-app.js / firebase-config.js   المزامنة السحابية وتسجيل الدخول
```

### لماذا فيه خطوة "تجميع" (Build)؟
`app.js` يستخدم مكتبة Firebase مباشرة. لضمان عملها بشكل موثوق داخل نافذة Electron، يتم "تجميعها" (bundling) عبر esbuild في ملف واحد `dist/bundle.js` هو اللي تحمّله `index.html` فعليًا. هذا يحصل تلقائيًا مع كل من `npm start` و`npm run dist` — ما تحتاج تسويه يدويًا.

> ملاحظة: بما إن `firebase-config.js` يُدمج داخل الحزمة وقت البناء، فأي تعديل عليه يحتاج إعادة بناء (`npm start` أو `npm run dist`) حتى يُطبّق. لو عندك عدة فروع بإعدادات مختلفة، سوّي نسخة مجلد منفصلة لكل فرع بإعداداتها الخاصة وابنِ exe مستقل لكل وحدة.

## النسخة الاحتياطية المحلية
بالإضافة للمزامنة السحابية، التطبيق الآن يحفظ نسخة من بياناته (المنتجات، المبيعات، المخزون) في ملف محلي على جهازك تلقائيًا بعد كل عملية، ويستعيدها عند إعادة الفتح — حتى لو ما فعّلت المزامنة السحابية إطلاقًا. هذا يعني البيانات ما تضيع بعد إغلاق البرنامج بعد اليوم.

## طباعة الفاتورة
زر "إتمام الدفع وطباعة الفاتورة" الآن يفتح فعليًا نافذة طباعة النظام (نفس نافذة الطباعة العادية بالويندوز) بعد كل عملية بيع.

## الصلاحيات المطبّقة
- **مدير النظام**: كل الشاشات + صافي الربح + حذف المنتجات.
- **مدير الفرع**: كل الشاشات ما عدا صافي الربح، ويقدر يضيف/يعدّل منتجات بدون حذف.
- **الكاشير**: شاشة نقطة البيع فقط.

## ملاحظة عن البيانات
البيانات محفوظة محليًا على جهازك بشكل دائم (تراجع القسم أعلاه)، وتُزامن سحابيًا أيضًا لو فعّلت Firebase. هذي نسخة تجريبية بمنتجات ابتدائية جاهزة — عدّلها من شاشة "المنتجات" كما تحب.

## تفعيل المزامنة السحابية (أونلاين/أوفلاين) — اختياري

التطبيق يشتغل بشكل طبيعي بدون هذه الخطوة (محليًا فقط). لو تبي المزامنة بين أكثر من جهاز/فرع:

1. روح إلى [console.firebase.google.com](https://console.firebase.google.com) وسوّي مشروع جديد (مجاني بالكامل لهذا الحجم من الاستخدام).
2. من القائمة الجانبية: **Build > Firestore Database > Create database**، واختر **Start in test mode** (تقدر تشدد القواعد لاحقًا).
3. من **⚙️ Project settings > Your apps**، اضغط أيقونة الويب `</>` وسجّل تطبيق جديد. راح يعطيك كائن `firebaseConfig`.
4. افتح ملف `firebase-config.js` داخل المشروع، واستبدل القيم بالقيم اللي نسختها.
5. شغّل `npm start` أو ابني `npm run dist` من جديد.

### كيف يشتغل أونلاين/أوفلاين
- إذا النت مقطوع، كل عملية بيع أو تعديل تُحفظ على الجهاز فورًا وتظهر شارة **"🟠 غير متصل — سيُحفظ ويُزامن لاحقًا"** في الشريط الجانبي.
- بمجرد رجوع الاتصال، Firestore يرسل كل التغييرات المعلّقة تلقائيًا للسحابة بدون أي تدخل، وتتحول الشارة إلى **"🟢 متصل — يتزامن الآن"**.
- زر **"⏸️ إيقاف المزامنة"** في الشريط الجانبي يفصل الاتصال يدويًا (مفيد لو تبي تشتغل أوفلاين قصدًا)، وزر **"▶️ تفعيل المزامنة"** يرجّعه ويزامن كل شي تراكم.
- إذا عندك أكثر من فرع وتبي كل فرع ببياناته منفصلة، غيّر قيمة `branchId` داخل `firebase-config.js` لكل نسخة مثبّتة على جهاز الفرع.

### ملاحظة أمان
وضع Test mode في Firestore يخلي القاعدة مفتوحة لأي شخص عنده الإعدادات لمدة 30 يوم فقط. قبل الاستخدام الفعلي، عدّل **Firestore > Rules** لقواعد أكثر تحكمًا (مثلًا تتطلب تسجيل دخول). إذا تبي، أقدر أساعدك تضيف تسجيل دخول لاحقًا يربط كل موظف بحساب حقيقي بدل اختيار الدور من الشاشة.

## تسجيل الدخول بحساب (بدل اختيار الدور يدويًا) — اختياري

يفعّل تلقائيًا بمجرد ما تعبّي `firebase-config.js` (نفس إعدادات المزامنة). خطوات الإعداد:

1. من Firebase Console: **Build > Authentication > Get started > Sign-in method**، فعّل **Email/Password**.
2. من **Authentication > Users > Add user**، أنشئ أول حساب (بريد + كلمة مرور) — هذا راح يكون أول مدير نظام.
3. من **Firestore Database**، سوّي Collection جديد اسمه `staff`، وجوه Document واحد يكون الـ ID تبعه هو نفس **UID** تبع المستخدم اللي أنشأته (تلقاه بجدول Authentication > Users). حط فيه الحقول:
   ```
   email: "البريد اللي سجلته"
   name: "اسم المدير"
   role: "admin"
   ```
4. افتح التطبيق، سجّل دخول بنفس البريد وكلمة المرور — بترى كل الشاشات بصلاحية مدير النظام، وبينها شاشة **"الموظفون"** لإضافة بقية الموظفين مباشرة من داخل التطبيق (بدون الرجوع لـ Firebase Console مرة ثانية).

إذا ما تبي تسجيل دخول بحسابات، اضغط رابط **"المتابعة بدون تسجيل دخول (وضع تجريبي)"** بشاشة الدخول ويرجعك لاختيار الدور القديم.

## التحديثات عن بعد (Auto Update) — اختياري

يخلي أي تحديث ترفعه يوصل تلقائيًا لكل نسخة مثبّتة عند المستخدمين، بدون ما يعيدوا التنصيب يدويًا.

1. سوّي مستودع (Repository) جديد على [GitHub](https://github.com) — عام أو خاص، الاسم يكون نفسه بالضبط اللي بتحطه بـ `repo` تحت.
2. افتح `package.json`، وتحت `"build" > "publish"` غيّر:
   ```json
   "owner": "اسم-حسابك-في-GitHub",
   "repo": "اسم-المستودع"
   ```
3. سوّي [Personal Access Token](https://github.com/settings/tokens) بصلاحية `repo`، وحطه كمتغيّر بيئة قبل أمر النشر:
   - ويندوز (PowerShell): `$env:GH_TOKEN="التوكن_هنا"`
   - ماك/لينكس: `export GH_TOKEN="التوكن_هنا"`
4. كل مرة تبي تنشر تحديث: زوّد رقم `"version"` بأعلى `package.json` (مثلًا من `1.0.0` إلى `1.0.1`)، ثم شغّل:
   ```
   npm run publish
   ```
   راح يبني الـ exe ويرفعه كـ Release جديد على GitHub تلقائيًا.
5. أي جهاز مثبّت عليه التطبيق (النسخة المبنية بـ `npm run dist`، مو `npm start`) بيتفحص عن تحديث عند كل فتح، ويحمّله بالخلفية، وتظهر رسالة بأعلى الشاشة "✅ التحديث جاهز — إعادة التشغيل الآن".

> ملاحظة: التحديث التلقائي ما يشتغل في وضع `npm start` (وضع التطوير) — يشتغل فقط بالنسخة المبنية والمثبّتة فعليًا على الجهاز.

## إغلاق اليوم وإرسال تقرير بالبريد — اختياري

زر **"🔒 إغلاق اليوم وإرسال التقرير"** موجود بلوحة التحكم لمدير النظام ومدير الفرع. عند الضغط عليه:
- يُرسل تقرير HTML مرتب (المبيعات، عدد الطلبات، آخر العمليات، تنبيهات المخزون) على بريدك.
- يصفّر أرقام اليوم (المبيعات، الطلبات، آخر العمليات) عشان يبدأ يوم جديد.

### تفعيل الإرسال
1. فعّل **التحقق بخطوتين** على حساب Gmail إذا مو مفعّل: https://myaccount.google.com/security
2. روح https://myaccount.google.com/apppasswords وسوّي **App Password** جديدة (اسمها أي شي، مثلاً "cafe-pos").
3. افتح `email-config.js` وحط بريدك و**كلمة مرور التطبيق** هذي (مو كلمة مرور حسابك العادية، هذي 16 حرف تولدها Google خصيصًا).
4. حدد بريد الاستلام بحقل `to` (تقدر تخليه نفس بريدك).

> بخلاف `firebase-config.js`، ملف `email-config.js` **لا يحتاج إعادة بناء** — يتحمّل مباشرة من قبل النظام (main process) وقت التشغيل، فتقدر تعدّله حتى بعد التثبيت (`npm run dist`) وياخذ مفعوله فورًا من غير ما تبني من جديد.

إذا ما عدّلت الملف، الزر لسا يشتغل ويصفّر الأرقام، بس بدون إرسال بريد (وتوصلك رسالة توضح ذلك).

## تغيير أيقونة التطبيق (اختياري)
ضع ملف `icon.ico` (لويندوز) داخل مجلد جديد اسمه `assets`، ثم أضف هذا السطر داخل `package.json` تحت `"win"`:
```json
"win": { "target": "nsis", "icon": "assets/icon.ico" }
```
